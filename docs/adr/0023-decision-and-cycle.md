# Design 0023 — Decision Engine and the cognitive cycle (steps 7b and 7c)

**Status:** Implemented · **Date:** 2026-08-23
**Implements:** RFC 022, RFC 021 · **Gate:** steps 6–7 — *cycle does not skip Decision/Policy*

## The Decision Engine separates deciding from answering

RFC 022 exists so that "what shall I say" and "what shall I do" are different questions with
different answers. Eight modes: respond, ask, create a goal, plan, wait, call a tool, refuse, or
stay silent.

**The six axes are structural.** Rule 1 requires every option to be evaluated on relevance,
evidence, risk, cost, permissions and reversibility. `OptionEvaluation` makes all six required at
construction, so an option that was not evaluated on all of them cannot be built at all. A runtime
check would have been forgettable; a required record is not.

**Privilege is never escalated.** An option the evaluation marks not permitted is dropped, not
granted because it scored well. An option with blocking reasons is not selected.

**High confidence with no source becomes a question.** The limit case is precise and the failure it
prevents is familiar: treating an unsourced confident claim as ground truth. The decision is reduced
to `ASK` and the reason is recorded in the uncertainty list.

**Silence is a closed set.** Rule 3 permits four reasons — channel rule, privacy, noise limit, no
recipient — and there is deliberately no value for hiding a fault. A cycle reporting a failure can
never be silent, and an invented reason is refused even when the channel claims to allow it.

**Two equivalent options resolve toward the smaller footprint:** less external effect first, then
lower cost, then reversibility. A tie that survives all three and still reaches outside Aurora
becomes a question rather than a coin toss.

**Rule 2 is enforced at commit:** a `TOOL_CALL` without an allowing policy decision cannot be
committed, and one that requires approval cannot be committed until it is satisfied.

## The cycle is a machine for refusing

RFC 021's rationale states the purpose exactly: the cycle exists so that a sentence generated by a
model cannot become an action or a memory. This implementation is mostly refusals, and each one maps
to a rule.

**No stage is jumped over.** Advancing to a stage requires every earlier one to have run or to carry
a recorded omission reason. An omission with a blank reason is refused, because a skipped stage
wearing a label is still a skipped stage.

The stage order is data, not control flow. That means *"did this cycle skip Decision?"* is a
question answerable from the record alone, months later, by someone who was not there.

**No stateful result before Decision and Policy.** A result declaring that it carries persistent
state or an execution outcome cannot be produced until both have run — the gate condition for this
step. A plain answer from context needs neither, which keeps the rule about effects rather than
about ceremony.

**No effect without policy.** Marking an execution requires the Policy stage to have run, to have
allowed it, and, where required, for the approval to be satisfied. Three separate refusals, because
each is a separate way to get it wrong.

**Observation and Reflection are mandatory after an execution**, even when reflection concludes
there is nothing to learn. "Nothing worth noting" is itself a record, and a system that only writes
down interesting outcomes has no baseline to compare them against.

**Interruption is survivable.** A cycle can wait for data, time, approval or availability and be
resumed; resuming is idempotent, and a completed or failed cycle records nothing further and cannot
be resumed at all.

## Tests

33 conformance tests across both RFCs. Decision: the six axes present; unpermitted and blocked
options dropped; confidence without evidence reduced to asking; silence requiring a permitted reason
on a permitting channel; a failing cycle never silent; an invented silence reason refused; tools
blocked when the motor is down and said so; the smaller footprint winning; two equivalent external
options becoming a question; commit refused without an allow and without a satisfied approval;
expiry; supersession; alternatives kept on the record.

Cycle: starting at Perception; a jumped stage refused and naming what was missing; omission with a
reason accepted and without one refused; a stateful result refused before Decision and Policy and
accepted after; a plain answer completing without them; an effect refused before Policy, when policy
denied, and when approval was unsatisfied; an executed cycle unable to close without Observation and
Reflection; reflection concluding nothing still counting; wait and resume preserving the stage;
resume idempotent; a finished cycle recording nothing further; and the stage record reading back in
the RFC's order.

## Not built yet

The **Planner** (RFC 05). The cycle has its stage and the stage can be omitted with a reason, which
is what a cycle without an explicit goal does today. Objectives, plans and task decomposition are
their own increment.

## Deferred

RFC 022's configurable utility, impact simulation and collegial decisions. RFC 021's parallel
priority cycles, simulation before execution and per-stage quality metrics. Wiring the cycle to
drive the existing Kernel path, which is step 10 work — the MCP surface belongs there, and the cycle
is the thing it will be rebuilt on.
